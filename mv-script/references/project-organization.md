# MV 项目目录整理

## 新建或继续项目

确定作品和版本，优先沿用用户指定的位置或已有项目目录。默认把每部 MV 放进共同父目录 `mv_project/` 下独立的同级文件夹。项目名用已有目录名或作品标题；同一部作品的长版、短版与局部试做留在该作品目录内。技能仓库与创作文件分开。只创建本轮要用的目录和文档。

```text
mv_project/
  README.md
  催眠/
    mv_script_short_20261114.md
    assets/
    storyboard_images/
  另一部MV/
    mv_script.md
    assets/
    storyboard_images/
```

共同父目录有多个项目时，`README.md` 可链接每部作品当前的剧本、资产索引、分镜、试剪和工作包。优先使用相对链接，已有可用的项目索引直接更新。参考原件位于外部时，在素材清单记下来源，由用户指定是否复制或移动原件。

## 整理已有目录

从用户指定范围盘点项目和文件。根据剧本标题、资产索引、分镜和工作包判断归属，把每部作品已有的内部目录关系尽量保留下来。列出旧位置到新位置的映射，先查目标重名、共享素材和文档跨项目引用。归属不清的文件暂留在原处，只有会影响搬迁的关键歧义才需要问用户。

用户要求实际整理时，按映射搬迁文件，优先移动完整子目录。发生重名时保留两份并记录各自版本。共享素材已有可用位置时，可保留原位置并更新引用。整理范围包括路径、索引与目录，保留原素材、旧版本和交付包。整理目录本身不授予删除素材、覆盖文件或改写创作内容的授权。

搬迁前后比对文件清单，对移入的原素材和交付包核对文件大小与哈希。检查此前可用的 Markdown 链接、项目索引、提示词和资产记录中的路径；对剪辑工程等工具管理的引用，用对应工具重新定位或标明待重新连接。只调整受影响的引用，检查新链接可打开。若发现丢失、覆盖或新断链，优先用移动映射恢复或修复，再报告新目录和仍需处理的项目。一个项目目录中的文件完整性应单独检查，尤其是被 Git 忽略的本地创作目录。

## 仓库与工作包

技能仓库可存放通用说明和获准使用的案例摘录。歌曲、身份参考、完整试剪和项目工作包留在对应项目目录。工作包有自己的结构，应按生成输入清单选取素材，见 [生成工作包规范](generation-package.md)。
